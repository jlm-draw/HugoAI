# HugoAI 项目目录结构

## 整体架构

```
HugoAI/                          ← 项目根目录
├── docs/                        ← 项目文档（设计稿、规划、规范等）
├── code/                        ← 所有代码
│   ├── front/                   ← 前端（Next.js 全栈应用）
│   └── backend/                 ← 后端（数据库、服务、任务等独立后端组件）
├── docker-compose.yml           ← Docker 编排文件（与 docs/、code/ 同级）
└── .gitignore                   ← 根目录 Git 忽略规则
```

> **原则：** 所有代码必须放在 `code/` 下，所有文档必须放在 `docs/` 下，`docker-compose.yml` 保持在根目录。

---

## code/front/ — 前端（Next.js 全栈应用）

Next.js 是全栈框架，前端项目包含完整的 UI 层和 API 层。

```
code/front/
├── src/
│   ├── app/                     ← Next.js App Router
│   │   ├── (auth)/              ← 认证相关路由组（登录、注册等）
│   │   ├── (dashboard)/         ← 仪表盘路由组
│   │   ├── api/                 ← API 路由（服务端接口）
│   │   ├── globals.css          ← 全局样式
│   │   ├── layout.tsx           ← 根布局
│   │   └── favicon.ico          ← 站点图标
│   ├── components/              ← 可复用 UI 组件
│   ├── lib/                     ← 工具函数和辅助库
│   │   ├── ai.ts                ← AI 相关工具函数
│   │   ├── auth.ts              ← 认证工具函数
│   │   ├── db.ts                ← 数据库连接工具
│   │   ├── rbac.ts              ← 基于角色的访问控制
│   │   ├── redis.ts             ← Redis 连接工具
│   │   └── utils.ts             ← 通用工具函数
│   ├── services/                ← 业务服务层
│   │   └── news/                ← 新闻相关服务
│   ├── jobs/                    ← 定时任务和后台作业
│   │   └── scheduler.ts         ← 任务调度器
│   ├── instrumentation.ts       ← OpenTelemetry 等可观测性配置
│   └── proxy.ts                 ← 代理配置
├── public/                      ← 静态资源（图片、字体等）
├── package.json                 ← 依赖管理
├── next.config.ts               ← Next.js 配置
├── tsconfig.json                ← TypeScript 配置
├── postcss.config.mjs           ← PostCSS 配置
├── eslint.config.mjs            ← ESLint 配置
├── components.json              ← shadcn/ui 配置
├── .env.local                   ← 本地环境变量（不提交）
├── .dockerignore                ← Docker 构建忽略文件
├── .gitignore                   ← 前端 Git 忽略规则
├── .playwright-mcp/             ← Playwright 测试工具
├── .superpowers/                ← 开发工具配置
└── storage/                     ← 本地存储目录
```

## code/backend/ — 后端（独立后端组件）

包含数据库、独立服务等不直接属于前端的后端代码。

```
code/backend/
├── prisma/
│   ├── schema.prisma            ← Prisma 数据库模型定义
│   ├── migrations/              ← 数据库迁移脚本
│   └── seed.ts                  ← 数据库种子数据
└── .env.example                 ← 后端环境变量模板
```

## 开发规范

> **所有参与开发的 Agent 必须遵守以下规则，不得违反。**

1. **文件放置位置**
   - 新增的前端代码（组件、页面、样式、脚本）→ `code/front/` 下对应目录
   - 新增的后端代码（数据库模型、迁移、独立服务）→ `code/backend/` 下对应目录
   - 新增的文档 → `docs/` 下对应目录
   - 新增的 Docker 配置 → 根目录 `docker-compose.yml`

2. **禁止行为**
   - ❌ 不要在根目录直接创建代码文件或目录（如 `src/`、`components/`、`pages/` 等）
   - ❌ 不要将代码文件放在 `docs/` 目录下
   - ❌ 不要将文档文件放在 `code/` 目录下
   - ❌ 不要删除 `docker-compose.yml` 或将其移入子目录

3. **路径引用**
   - 在文档、注释、配置中引用路径时，使用相对路径并注明基准目录，如 `code/front/src/app/`
   - 导入模块时遵循 Next.js 的项目约定

4. **新增目录时**
   - 如果在 `code/front/` 下新增目录，需遵循 Next.js 约定式路由规范
   - 如果在 `code/backend/` 下新增目录，需确保路径在 `.gitignore` 中有适当配置

5. **gitignore 规则**
   - 根目录 `.gitignore` 必须覆盖所有子项目的忽略项
   - `code/front/.gitignore` 专门处理 Next.js 相关的忽略规则
